# XDeck

X（Twitter）の検索結果やタイムラインを複数カラムで横並び閲覧するための、個人利用向けデスクトップアプリ（Windows）。

同じアプリの実装が 2 つあります。機能は同じです。

| | Tauri 版（メイン） | Electron 版 |
| --- | --- | --- |
| 場所 | [`tauri/`](tauri/) | リポジトリ直下 |
| 中身 | Rust + WebView2（Windows 標準の Edge エンジン） | Electron（Chromium 同梱） |
| 配布サイズ | exe 1 つ（約 8MB） | フォルダ一式（約 260MB） |
| 設定の保存先 | `%APPDATA%\com.xdeck.tauri-prototype\` | `%APPDATA%\xdeck\` |

今後は **Tauri 版をメイン**にしています。動作が軽く（アイドル時の CPU は Electron 版の約 6 割）、配布も exe 1 つで済みます。
メモリ使用量はほぼ同じです。Electron 版は比較用・予備として残しています。

## Tauri 版の動かし方

前提: Rust（`rustup`）、Visual Studio の C++ ビルドツール、WebView2（Windows 11 は標準で入っています）。

```powershell
cd tauri/src-tauri
cargo run              # 開発用ビルドで起動
cargo build --release  # 配布用 → tauri/src-tauri/target/release/xdeck-tauri.exe
```

`xdeck-tauri.exe` は単体で動くので、どこにコピーしても起動できます。
ビルドし直すときは、起動中の XDeck を閉じてから実行してください（exe が使用中だと上書きできません）。

- 初回起動時、Electron 版のカラム設定（`%APPDATA%\xdeck\columns.json`）があればコピーして使います。
- ログイン状態は Electron 版と共有されません。どれか 1 カラムで **ID/パスワードで**ログインしてください
  （Google/Apple ログインは別ウィンドウを使うため動きません）。
- 構成や Electron 版との仕組みの違いは [`tauri/README.md`](tauri/README.md) を参照してください。

## Electron 版の動かし方

```bash
npm install
npm start
```

初回起動時、Windowsから「パブリックネットワークとプライベートネットワークへのアクセスを許可しますか」という
ファイアウォールの確認が出ます。**許可**を選んでください（X.comへの通信に必要です）。

## 使い方（両方共通）

1. 上部のフォームでカラム種別を選ぶ。
   - 「検索」: 検索キーワードとソート順（最新/話題）を指定して「＋カラム追加」。キーワード欄の右にある
     チェックボックス（日本語/メディア/RT除外/返信除外）で検索演算子（`lang:ja` / `filter:media` /
     `-filter:retweets` / `-filter:replies`）を`q=`に注入できます。既定はすべてOFF。追加後も現在どの
     演算子が有効かはカラムの`⚙`から確認・変更でき、変更すると即座にその内容で再検索されます。
   - 「ホーム」: `x.com/home` を表示するカラム。「おすすめ/フォロー中」タブは非表示にしていますが、
     カラムの`⚙`にある「表示」でどちらを表示するか選べます（既定はフォロー中）。カラムのタイトルにも
     現在どちらが選ばれているか（例:「ホーム・フォロー中」）が表示されます。投稿ボックス（「いまどうしてる？」）
     も非表示にし、閲覧スペースを最大化しています（投稿は下記の「✎ ポストする」から行えます）。
   - 「通知」: `x.com/notifications` を表示するカラム（「すべて/@ツイート」タブは非表示。既定で「すべて」が
     選択された状態なので、通知全般がそのまま表示されます）。
   - 「話題を検索」: Xの「話題を検索」ページ（`x.com/explore/tabs/for-you`）。タブバーは非表示ですが、
     カラムの`⚙`にある「表示」でおすすめ/トレンド/ニュース/スポーツ/エンタメを切り替えられます（既定はおすすめ）。
   - 「トレンド」: X全体のトレンド一覧（`x.com/explore/tabs/trending`）。
   - 「ホーム」「通知」「話題を検索」「トレンド」ではキーワード入力欄は不要になり自動的に隠れます。
2. 追加したカラムは自動的に `columns.json`（保存先は上の表）に保存され、次回起動時も復元されます。
   ウィンドウの位置・サイズ（最大化していたかどうかも含む）も保存され、次回起動時に復元されます。
3. **ログイン**は特別な仕組みを用意していません。いずれか1つのカラムでXのログイン画面が出るので、そこで直接ログインしてください。
   全カラムが同じセッションを共有しているため、一度ログインすれば他のカラムにも、次回起動時にも引き継がれます。
4. 各カラムのヘッダーにあるボタン：
   - `⠿` ドラッグして並べ替え（他のカラムの上にドロップすると入れ替わります）
   - `⌂` トップ（検索/ホーム/トレンドそれぞれの元のURL）に戻る
   - `←` ブラウザの「戻る」
   - `⤒` / `⤓` 一番上 / 一番下へスクロール
   - `⟲` 差分更新（新着だけを取り込み、スクロール位置は維持）
   - `⟳` 手動更新（ページ全体を再読み込み）
   - `⚙` そのカラムの「文字サイズ」「自動更新」、検索カラムなら並び替え・検索演算子、ホームカラムなら
     表示（おすすめ/フォロー中）の設定を開閉（下記5参照）
   - `✕` カラム削除

   カラムの右端（境界線）をドラッグすると幅を自由に変更できます（280px〜900px、`columns.json`に永続化）。
   右上の「⟲ 全カラム更新」で全カラムをまとめて差分更新できます。
5. 文字サイズ（80%〜150%）と自動更新間隔（オフ/1分/3分/5分/10分、既定は3分）は**カラムごと**に`⚙`から設定できます
   （既定では非表示。`⚙`をクリックした時だけ開くパネルです）。
   検索カラムは「並び替え」（最新/話題）も`⚙`から後から変更でき、変更すると即座にその並び順で再検索されます
   （Xの検索・ホームともに、この並び替え/表示のタブバー自体はアプリ側で非表示にしているため、`⚙`が唯一の
   切り替え手段です）。
   自動更新はフルリロードではなく差分更新です。新着があればページ遷移なしでその場に反映され、
   新着が無ければ何も起きません。
6. 投稿は右上の「✎ ポストする」ボタンから。同じセッションを使う小さなポップアップウィンドウで
   `x.com/compose/post`（Xの投稿専用画面）を開きます。各カラムはあくまで閲覧専用（投稿ボックス等は
   非表示）にして、投稿の導線はこのボタン1つに集約する設計にしています。投稿が成功すると、このポップアップは
   自動的に閉じます（Xの内部API `CreateTweet` の通信が成功（2xx）したことを検知して閉じる方式。通信が
   失敗した場合はウィンドウが開いたままなので、その場でリトライできます）。
7. タイムライン上の広告（プロモーション投稿）は全カラムで自動的に非表示になります。無限スクロールで後から
   読み込まれる投稿にも`MutationObserver`で追従します。広告は`data-testid`等の安定した目印を持たない素の
   `<span>`で「広告」と表示されるだけなので、テキスト内容で判定しています（ツイート本文は判定対象から除外し、
   本文にたまたま「広告」という言葉が含まれていても誤って隠さないようにしています）。
8. ツイート内のリンクや外部サイトのカードをクリックすると、アプリ内には表示せず**OSの既定のブラウザ**で開きます。
   x.com内のリンク（プロフィールなど）はそのままカラム内で遷移します。
9. その他:
   - 写真をクリックすると画像ビューアのウィンドウで開きます（`←` `→` で前後の画像、`Esc` で閉じる）。
   - ハッシュタグをクリックすると、そのハッシュタグの検索カラムが右隣に追加されます。
   - 動画の自動再生は止めています。動画の全画面表示もできます。
   - カラムの上で横ホイール（または Shift+ホイール）を回すと、カラム一覧が横にスクロールします。
   - ウィンドウにはOSのタイトルバーがなく、ツールバーがその代わりです（空いている所をドラッグで移動、
     ダブルクリックで最大化）。最小化・最大化・閉じるボタンは右上にあります。

## 不要UIの非表示（CSS注入）について

[`inject.css`](inject.css) がタイムライン以外の要素（左ナビ、右サイドバーのトレンド/おすすめ、投稿ボタン、
**Xが自前で表示する検索ボックスや「話題のポスト/最新」等のタブバー**、ホーム画面の「タイムラインを管理」
ボタンとその余白など）を `display: none` で隠しています。Tauri 版・Electron 版で同じファイルを使っています。
子要素だけを隠すとその親の空き枠（余白）が透けて残ってしまうことがあるため、`:has()`で「対象を含み、
かつタイムライン本体（`article`）は含まない」親要素ごと隠すようにしています。
X（Twitter）はDOM構造やクラス名を頻繁に変更するため、**このファイルは壊れる前提**で設計してあります。

- 不要な要素が復活してきたら、開発者ツールで要素を検証し、`data-testid` 属性などの安定したセレクタを探して
  `inject.css` に追記してください。
  - Tauri 版: 開発用ビルド（`cargo run`）でカラムを右クリック →「検証」。`inject.css` はビルド時に
    埋め込まれるので、編集後はビルドし直してください。
  - Electron 版: カラムにマウスを乗せて **F12**。起動したまま `inject.css` を保存すると全カラムに即座に再適用されます。

## Electron 版の exe 化（配布用パッケージの作成）

```bash
npm run package:win
```

`node_modules\electron\dist`（`npm install`済みのElectronランタイム）をそのまま流用し、`resources\app`に
アプリのソースを配置する形で `dist\XDeck-win32-x64\XDeck.exe` を組み立てます（内部は
[`build-package.ps1`](build-package.ps1)）。インストーラーは作りません。生成される`dist\XDeck-win32-x64`フォルダ一式
（約260MB、Chromium同梱のため）をまるごとコピー/zipすれば、Node.js未インストールの環境でも`XDeck.exe`を
ダブルクリックするだけで起動できます。

コード変更後の再ビルドは同じコマンドで、`resources\app`配下のソースだけ上書きされます。
Electronのバージョン自体を上げた場合は`dist\XDeck-win32-x64`フォルダを削除してから実行してください。

## Electron 版の技術構成

- `main.js` — Electronメインプロセス。カラム構成の読み書き（JSON）、`inject.css`のファイル監視、外部リンクを
  既定ブラウザで開く処理を担当。
- `preload.js` — `contextBridge` でレンダラーに `window.xdeck` として最小限のAPIを公開（`contextIsolation: true`）。
- `index.html` / `styles.css` — アプリ全体のシェル（ツールバー、カラムを横並びにするコンテナ）。
- `renderer.js` — カラムの追加・削除、`<webview>` の生成、CSS再注入、自動更新タイマーを制御。
- `inject.css` — 各カラムのx.comのページに注入するCSS（Tauri 版と共用）。

各カラムは `<webview partition="persist:xsession">` として実装しており、これが「複数アカウント不要・単一セッション
共有・ディスクへの永続化」を同時に満たしています。
文字サイズはCSSの`zoom`を各カラムに個別注入して実現しています（`webview.setZoomFactor()`は同じオリジンの
全カラムに影響してしまうため不採用）。

Tauri 版の構成は [`tauri/README.md`](tauri/README.md) を参照してください。

## 既知の制約

- `inject.css` のセレクタはX側の変更で壊れる可能性があります（上記「不要UIの非表示について」参照）。
- Electron 版には、ウィンドウ全体が再読み込みされる不具合があります（GPU プロセスのクラッシュが原因。未解決）。
