# XDeck

X（Twitter）の検索結果を複数カラムで横並び閲覧するための、個人利用向けデスクトップアプリ（Electron製）。

## セットアップ

```bash
npm install
npm start
```

初回起動時、Windowsから「パブリックネットワークとプライベートネットワークへのアクセスを許可しますか」という
ファイアウォールの確認が出ます。**許可**を選んでください（X.comへの通信に必要です）。

## 使い方

1. 上部のフォームでカラム種別を選ぶ。「検索」なら検索キーワードとソート順（最新/話題）を指定して「＋カラム追加」。
   「トレンド」を選ぶと、X全体のトレンド一覧（`x.com/explore/tabs/trending`）を表示するカラムが追加できる
   （キーワード入力欄は不要になり自動的に隠れます）。
2. 追加したカラムは自動的に `%APPDATA%\xdeck\columns.json` に保存され、次回起動時も復元されます。
3. **ログイン**は特別な仕組みを用意していません。いずれか1つのカラムでXのログイン画面が出るので、そこで直接ログインしてください。
   全カラムが同じセッション（`persist:xsession` パーティション）を共有しているため、一度ログインすれば
   他のカラムにも、次回起動時にも引き継がれます。
4. 各カラムのヘッダーにあるボタン：
   - `⠿` ドラッグして並べ替え（他のカラムの上にドロップすると入れ替わります）
   - `⌂` 検索トップ（元の検索URL）に戻る
   - `←` ブラウザの「戻る」
   - `⟳` 手動更新
   - `🔍` DevTools（下記のCSS調整で使用）
   - `✕` カラム削除
5. 右上の「文字サイズ」で全カラムの表示倍率（80%〜150%）を、「自動更新」でリロード間隔を設定できます。
   文字サイズは`<webview>`のズーム機能（ブラウザのCtrl+/-相当）で実現しています。Xの文字サイズはCSSの
   `font-size`が要素ごとに固定pxで指定されており単純なCSS上書きでは崩れやすいため、拡大縮小はズームで統一しています。
   設定は`%APPDATA%\xdeck\settings.json`に保存され、次回起動時も復元されます。

## 不要UIの非表示（CSS注入）について

[`inject.css`](inject.css) がタイムライン以外の要素（左ナビ、右サイドバーのトレンド/おすすめ、投稿ボタン、
**Xが自前で表示する検索ボックスや「話題のポスト/最新」等のタブバー**など）を `display: none` で隠しています。
検索・ソート切り替えはアプリ側のツールバー（キーワード入力・ソートのプルダウン・カラム種別選択）で行う設計なので、
各カラムは結果だけを表示する「出力用」の画面になります。X（Twitter）はDOM構造やクラス名を頻繁に変更するため、
**このファイルは壊れる前提**で設計してあります。

- アプリを起動したまま `inject.css` を編集して保存すると、開いている全カラムに即座に再適用されます（再起動不要）。
- 不要な要素が復活してきたら、カラムの `🔍` ボタンでDevToolsを開き、該当要素を検証（Inspect）して
  `data-testid` 属性などの安定したセレクタを探し、`inject.css` に追記してください。

## exe化（配布用パッケージの作成）

```bash
npm run package:win
```

`node_modules\electron\dist`（`npm install`済みのElectronランタイム）をそのまま流用し、`resources\app`に
アプリのソースを配置する形で `dist\XDeck-win32-x64\XDeck.exe` を組み立てます（内部は
[`build-package.ps1`](build-package.ps1)）。`electron-builder`/`electron-packager`のようなインストーラー生成は
行っていません（この環境ではzip展開処理が不安定だったため）。生成される`dist\XDeck-win32-x64`フォルダ一式
（約260MB、Chromium同梱のため）をまるごとコピー/zipすれば、Node.js未インストールの環境でも`XDeck.exe`を
ダブルクリックするだけで起動できます。

コード変更後の再ビルドは同じコマンドで、既存の`XDeck.exe`（Electron本体）はそのまま再利用し、
`resources\app`配下のソースだけ上書きされます。Electronのバージョン自体を上げた場合は
`dist\XDeck-win32-x64`フォルダを削除してから実行してください。

## 技術構成

- `main.js` — Electronメインプロセス。カラム構成の読み書き（JSON）、`inject.css`のファイル監視、外部リンクを
  既定ブラウザで開く処理を担当。
- `preload.js` — `contextBridge` でレンダラーに `window.xdeck` として最小限のAPIを公開（`contextIsolation: true`）。
- `index.html` / `styles.css` — アプリ全体のシェル（ツールバー、カラムを横並びにするコンテナ）。
- `renderer.js` — カラムの追加・削除、`<webview>` の生成、CSS再注入、自動更新タイマーを制御。
- `inject.css` — 各カラム（＝各 `<webview>` が表示するx.comのページ）に注入するCSS。

各カラムは `<webview partition="persist:xsession">` として実装しており、これが「複数アカウント不要・単一セッション
共有・ディスクへの永続化」を同時に満たしています。

## 既知の制約（MVPとして割り切っている点）

- 自動更新は `webview.reload()` によるフルリロードです（スクロール位置は保持されません）。よりスムーズな
  差分更新にするなら、X内蔵の「新着ツイート」ピルをJS経由でクリックする方式への改善余地があります。
- カラムの並べ替え（ドラッグ&ドロップ）は未実装です。削除して追加し直すか、`columns.json` を直接編集してください。
- `inject.css` のセレクタはX側の変更で壊れる可能性があります（上記「不要UIの非表示について」参照）。
